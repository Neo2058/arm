# Личный табель: подключение интерфейсов

Этап начат 27 октября 2026 по подтверждённому плану. Production не обновлять отдельно
от миграций и общего API. Каноническая карусель остаётся прежней.

- [x] Общая клиентская модель: формы, копейки, сохранённая операция, повтор без нового UUID.
- [x] Веб: календарь v2, карточка смены, параметры месяца, доступ из профиля; старый календарь отдельно.
- [x] Android: тот же сценарий из профиля, приватные черновики по серверу/пользователю.
- [x] Проверки конфликтов/сети, сборки JS, серверные регрессии; зафиксировать ограничения.

Расчёты выполняются только сервером. Прогноз не включает неподтверждённые компоненты зарплаты.
Изменение настроек не пересчитывает сохранённые смены без явного обновления снимка.

## Реализовано

Веб: `/account` → «Личный табель» → `/worktime`. Остров WorkTime монтируется вместо
старого WorkCalendar, который доступен кнопкой «Старый календарь». Карусель не изменена.
В календаре допускается несколько смен за день. Старые записи не конвертируются и не
складываются с новым прогнозом. Отклонения старого календаря также исключены явно.

APK: «Профиль» → «Личный табель · смены и параметры». Отдельный экран в стеке профиля,
без дополнительной нижней вкладки. Доступны календарь и список месяца, карточка смены,
линия/резерв/поверхность, оплачиваемые перерывы, код ночной связки, места начала/окончания,
предпросмотр и редактирование, помесячные ставки, проценты и подтверждённые выходные.

Точные часы, зачтённые и фактические ночные, начисления по видам работы и отдых берутся
из общего API. Новых формул зарплаты на клиентах нет. В месячном ответе добавлены время
и код смены, а в интервалах отдыха — границы соседних дежурств для понятного отображения.
Предпросмотр одной смены отдельно предупреждает, что ночная связка уточняется в сводке.

## Сеть, черновики и конфликты

- Общая модель `mobile/src/worktime/model.mjs`, контроллер React создаётся фабрикой
  `controller.mjs`: веб и APK используют собственный экземпляр React, правила запросов общие.
- Веб хранит ввод и запрос в sessionStorage, с областью origin + user ID. Данные переживают
  перезагрузку этой вкладки; закрытие вкладки может их удалить. Это не постоянная офлайн-база.
- APK использует приватный журнал FileSystem с областью API URL + user ID,
  namespace `personal-worktime`, с чтением предыдущей завершённой ревизии при неполной записи.
  Повторный вход сохраняет запросы, явный выход удаляет область. Проверка поколения блокирует
  позднюю запись после выхода. Секреты и одноразовые ссылки Telegram в табеле не сохраняются.
- Перед отправкой сохраняются точные URL, метод, тело, UUID и expected_revision.
  При сетевой ошибке/неподтверждённом ответе доступен ручной повтор того же запроса.
  Ввод нельзя незаметно заменить новым UUID, пока результат неизвестен. Фоновой отправки нет.
- 422 разрешает исправить поля. 409 требует загрузить актуальную запись, сравнить её
  с оставленным в форме вводом и явно продолжить с новой редакцией. Автоперезаписи нет.
  Для настроек повторно накладываются только первоначально изменённые поля, остальные
  конкурентные изменения сохраняются. 401/419 требуют повторного входа, запрос остаётся.
- При смене месяца форма остаётся привязана к исходной карточке/месяцу; сводка явно
  показывает выбранный месяц. При переносе смены в другой месяц нужно включить обновление снимка.

## Где остановились и что дальше

Интерфейсы готовы локально. Новых событий ClickHouse, изменений тарифных формул
или официальных ЛС/PLANIR в этой итерации нет. Полная совместимость CNTSMEN остаётся долгом.
Следующая контрольная точка — ручная приёмка веб/APK и совместная выкладка сервера,
миграций 100000/110000, веб-сборки и APK. До неё установленная серверная версия прежняя.
Релизу нужен отдельный номер версии; текущие 1.0.11/code12 оставлены без изменения,
поскольку рабочее дерево содержит также незавершённые изменения профиля и журнала.
Локальный APK `mobile/artifacts/tch15-worktime-local-2026-10-27.apk` не публиковать отдельно
от нового API. Он собран из всего текущего рабочего дерева, не является изолированным релизом табеля.

Дальнейшая денежная часть: подтвердить базы классности/выслуги/премии, сверхурочные,
налоги/алименты/профсоюз/аванс и ручные корректировки. До этого не добавлять предположительные
поля или формулы и не выдавать частичный итог за точную зарплату.
