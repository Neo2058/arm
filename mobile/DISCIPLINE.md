# Поручения руководителя в мобильном приложении

Первый этап интеграции, Android 1.0.5 (versionCode 6), Expo SDK 57.

## Возможности

У пользователя с ролью `instructor` появляется раздел «Поручения». Он показывает только назначенные этому пользователю исполнения: срок, состояние, просрочку, автора и непрочитанные события. Доступны фильтры, постраничная загрузка, ручное обновление и опрос каждые 30 секунд, пока раздел открыт и приложение активно.

Карточка содержит задание, требования к тексту и приложениям, историю сдач и решений. Инструктор отправляет ответ с PDF/JPEG/PNG в категориях «Отчёт», «Объяснение» и «Приложение». После возврата можно исправить результат и отправить новую попытку. Принятие и возврат выполняет руководитель в существующем веб-модуле ARM. Отправка сама по себе не завершает поручение.

Ранее отправленные файлы просматриваются внутри приложения. PDF отрисовывается через существующий PDF.js, картинки — нативным Image. Байты запрашиваются с Bearer-токеном; публичные адреса MinIO и signed URL для этих вложений не выдаются. При каждом чтении сервер заново проверяет пользователя и принадлежность исполнения.

## Серверный API

Все маршруты находятся внутри существующей группы `auth:sanctum` + `EnsureActiveApiUser`, дополнительно требуют текущую роль инструктора:

| Метод | Путь после `/api/mobile` | Назначение |
| --- | --- | --- |
| GET | `/discipline?status=…&page=…&per_page=…` | Личный список, непрочитанные события и лимиты |
| GET | `/discipline/{assignment}` | Карточка и последние 20 попыток |
| GET | `/discipline/{assignment}/reports?page=…` | Более ранняя история |
| POST | `/discipline/{assignment}/read` | Отметить собственные события прочитанными |
| POST | `/discipline/{assignment}/submit` | Сдача через общий DisciplineService |
| GET | `/discipline/files/{file}` | Авторизованный поток своего вложения |

Сдача использует multipart: `operation_id`, `version`, `response`, `report_files[]`, `explanation_files[]`, `other_files[]`. Идентификаторы и версии в ответах представлены строками. Лимиты — до пяти файлов, до 10 МиБ каждый и 25 МиБ суммарно. Тип, размер, требования, ClamAV, история и переходы состояний проверяются общим серверным сервисом. Бизнес-логика веб-модуля не дублируется и не меняется. Новых миграций нет: нужна уже установленная схема `discipline_*`.

Доступ к чужому исполнению/файлу — 404, неподходящая роль — 403, отсутствующий/отозванный токен — 401. JSON и файлы имеют Cache-Control private, no-store.

## Повтор отправки и границы первого этапа

Перед отправкой приложение фиксирует UUID операции, исходную версию, текст и список выбранных файлов. После сетевого сбоя либо ошибки сервера повторяется тот же запрос с тем же ключом; редактирование заморожено до определённого результата. Это позволяет получить квитанцию операции, даже если первый ответ потерялся после COMMIT. Одновременные повторные нажатия блокируются. При подтверждённой ошибке валидации либо конфликте версия и история перечитываются, локальный ответ сохраняется для исправления.

На этом этапе черновик и ожидающий запрос находятся в памяти. Не закрывайте приложение до получения подтверждения: системный кеш выбранных файлов и состояние формы не являются долговременным хранилищем. Сохранение черновиков между запусками, очередь офлайн-действий и отправка после восстановления интернета — следующий этап. Push-уведомления в фоне пока не добавлены; сейчас есть непрочитанные события и обновление открытого раздела.

При 401 нужно выйти через профиль и войти заново. Между пользователями экраны размонтируются; чужие данные сервер не возвращает. Остальные разделы рабочего места инструктора переносятся после завершения очереди/черновиков.

## Сборка и проверка

Добавлены только `expo-document-picker` и `expo-crypto` версий для SDK 57. После изменения нативных зависимостей требуется новый APK/IPA; один JS-export не обновляет установленный бинарник. Конфигурация подписи сохранена. В Android app/build.gradle при ручной сборке должны быть versionName 1.0.5 и versionCode 6; обновляйте генерируемый проект без удаления пользовательской настройки release signing.

Документация SDK: [DocumentPicker](https://docs.expo.dev/versions/v57.0.0/sdk/document-picker/), [Crypto](https://docs.expo.dev/versions/v57.0.0/sdk/crypto/). Выбор файлов использует copyToCacheDirectory для доступа к URI выбранных файлов.

```sh
php -d memory_limit=512M vendor/bin/phpunit --filter MobileDisciplineTest
node --test mobile/tests/*.cjs
cd mobile
npx expo export --platform android
```

Проведены 357 PHP-тестов и 12 JS-тестов, включая повтор с тем же ключом, конфликт версии, требования к файлам, приватность вложений, отзыв доступа и общий цикл сдача → возврат → повторная сдача → принятие. Полная проверка использует отдельную БД; production-данные для тестов не используются. Антивирус и хранилище в автоматических тестах подменяются; рабочий ReportScanner не изменён и остаётся обязательным.

Перед использованием APK на рабочем сервере нужно отдельно выложить новый API и обновить кеш маршрутов, сохраняя действующую конфигурацию ClamAV/MinIO. Затем устанавливается APK. Старые версии мобильного приложения продолжают работать: существующие маршруты и форматы не изменены. Эта локальная реализация сама по себе не обновляет production или установщик на странице `/install`.

Нативная проверка выполнена на отдельном Android-эмуляторе с локальным API и тестовыми пользователями: вход инструктора, личный список, выбор PDF, отправка multipart, искусственная потеря ответа после сохранения и повтор без дубликата, просмотр PDF, возврат руководителем, новая попытка и принятие. Финальный подписанный APK 1.0.5 установлен отдельно, проверен запуск экрана входа; тестовый адрес API и разрешение cleartext в итоговую сборку не включены. iOS-сборка не проверялась. Локальный установщик: `mobile/artifacts/tch15-android-1.0.5.apk`; он не добавляется в Git.
