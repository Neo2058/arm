## API и общий сервис

Все изменения веб-журнала и нового API идут через `App/Services/Journal/JournalTasks`:

| Метод | URI после `/api/mobile` | Данные |
| --- | --- | --- |
| POST | `/journal/tasks` | operation_id, title, description?, due_date? |
| PATCH | `/journal/tasks/{id}` | operation_id, version, title, description?, due_date? |
| POST | `/journal/tasks/{id}/complete` | operation_id, version |
| DELETE | `/journal/tasks/{id}` | operation_id, version |

`operation_id` — UUID. Повтор идентичного запроса возвращает сохранённую квитанцию, включая повтор удаления уже удалённой задачи. Другой запрос с тем же UUID — 409. Ключи разделены по пользователю; регистр UUID нормализуется. Идентификаторы и версии выдаются строками. Несовпавшая версия — 412 с `current`, содержащим доступную текущую задачу.

В транзакции блокируются текущая учётная запись (PostgreSQL FOR NO KEY UPDATE), профиль и задача. Проверяются свежая роль instructor, активность, владелец и текущая колонна. Колонна/владелец не принимаются от клиента. Мобильное создание без назначенной колонны отклоняется. Квитанция тоже требует прежнюю колонну и текущий доступ; смена роли/колонны не даёт читать старые результаты. Версия увеличивается также при изменениях из веба; новые веб-формы передают UUID и version; устаревшая форма возвращается к журналу с понятным сообщением. Старые формы без version сохраняют совместимость. Повторное выполнение уже выполненной задачи не увеличивает версию и не пишет повторное событие.

Максимум 255 символов названия и 20 000 описания; due_date — действительная дата ГГГГ-ММ-ДД либо null. Явный null очищает описание/срок; отсутствие поля при PATCH сохраняет его значение. Эти запросы различаются в fingerprint. Мобильное создание всегда source=manual. Существующие события journal.todo.* / normative_completed отправляются после COMMIT, без новой схемы ClickHouse; повтор квитанции события не дублирует. Отказ аналитики не отменяет принятую задачу.

## Мобильная форма и сохранение

`journal/mutations.cjs` хранит черновик, зафиксированный запрос и результат в отдельном приватном пространстве `journal-tasks`, разделённом по адресу API и user id. Токен в эти файлы не записывается. Используется существующий FileSystem-журнал с предыдущей завершённой ревизией.

Перед первым запросом снимок записывается на устройство. Ошибка записи блокирует отправку. При сетевом сбое либо потере ответа сохраняются тот же UUID, версия и содержимое; доступна ручная повторная отправка, в том числе после перезапуска приложения. До подтверждения нельзя начать другую операцию. Автоматической фоновой доставки операций личного журнала пока нет; автоматическая очередь поручений продолжает работать отдельно.

412 сохраняет введённый текст и предлагает проверить новую версию перед повтором; 422 позволяет исправить поля. 401 требует повторного входа через профиль с сохранением черновиков. Выход останавливает запросы и удаляет оба локальных пространства — поручений и личных задач. Удаление и выполнение требуют подтверждения; мобильный экран не меняет результат в списке до подтверждения API.
