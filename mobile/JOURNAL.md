# Мобильный журнал инструктора — Android 1.0.7

В разделе «Поручения» добавлена кнопка «Журнал инструктора». Доступна сводка текущей колонны, просмотр собственных задач с фильтрами «Все / К выполнению / Выполнены» и бригада с датами нормативов. Списки загружаются постранично, обновляются вручную и раз в 30 секунд при открытом активном экране. Новых нативных зависимостей нет.

## Общая логика и доступ

`App/Services/Journal/JournalOverview` формирует сводку для существующего веб-журнала и нового API. Число сотрудников относится к колонне; задачи, документы и рапорты — к пользователю и его текущей колонне. Процент нормативов сохраняет определение веб-версии: доля записей колонны с заполненным last_date; это не доля непросроченных нормативов.

| GET после `/api/mobile` | Результат |
| --- | --- |
| `/journal` | Колонна, счётчики и сообщение при отсутствии колонны |
| `/journal/tasks?status=pending&page=1&per_page=25` | Только личные задачи текущей колонны; status также done либо отсутствует |
| `/journal/crew?page=1&per_page=25` | Машинисты текущей колонны, девять видов нормативов по каждому |

Все маршруты требуют Sanctum, активную учётную запись и текущую роль instructor. Даже администратор не получает этот API. Колонна берётся из свежего профиля; клиент не задаёт владельца либо колонну. Без колонны — пустые списки и нулевые счётчики. Размер страницы ограничен 50.

Нормативы выдаются только для instructor_id текущего инструктора и текущей колонны; даты чужого инструктора не раскрываются. Если запись ещё не создана веб-журналом, мобильный экран явно показывает отсутствие записи. GET не создаёт строки, не меняет даты и настройки. Источником last_date / next_date является существующая БД; расчёт периодичности не дублируется. JSON имеет Cache-Control private, no-store; поля пути документов, email и телефоны бригады не выдаются.

## Границы выпуска

Это просмотр журнала. Создание, исправление, выполнение и удаление личных задач пока остаются в веб-версии, как и редактирование нормативов, настройки, история ClickHouse, отпуска, документы и поиск по нарядам. Поручения руководителя и их отчёты продолжают работать отдельно через DisciplineService и существующую очередь.

Данные журнала не добавлены в долговременный офлайн-кеш. При потере сети показывается ошибка обновления; уже открытый экран может показывать ранее полученные данные до ухода с него. 401/403 очищают данные экрана. Для следующего шага записи задач нужен общий сервис мутаций и устойчивый ключ операции; для нормативов — отдельные проверки владения и текущей колонны до изменения дат. Новых миграций и событий ClickHouse в этом выпуске нет.

## Проверка

- Полный набор PHP: 366 тестов, 1806 проверок.
- MobileJournalTest + JournalAccessTest: 39 тестов, 126 проверок: роли, отсутствие колонны, чужой владелец, смена колонны, пагинация, валидация фильтров, отсутствие записи при GET, совпадение статистики веба и API, деактивация и отзыв токена.
- Существующие 20 JS-тестов прошли, Android JS export выполнен.
- Android: вход инструктора, сводка, личные задачи, фильтр выполненных, бригада своей колонны и просроченные нормативы проверены на локальном API с отдельной БД. Итоговый подписанный APK также устанавливается отдельно и проверяется на запуск без тестового токена. iOS не проверялась.

Команды: `php -d memory_limit=512M vendor/bin/phpunit`; `node --test mobile/tests/*.cjs`; из mobile — `npx expo export --platform android`.
