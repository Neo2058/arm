# История событий: очистка и ручной архив

Согласовано и применено 09.11.2026 после приёмки владельцем обзорного видео 5:16. Видеоряд завершён; текст и звук готовит владелец.

## Действующий режим

- Только `default.user_actions`: раз в 72 часа удаляются записи с `event_time` старше 72 часов на момент запуска. Между запусками возраст сохранённых событий может приближаться к шести суткам.
- Автоматических архивов нет — выбор владельца. Если сведения потребуются позже, их нужно выгрузить **до** ближайшей очистки. Без ручной копии удалённая история невосстановима.
- PostgreSQL, документы, результаты обучения, смены, чат и системные логи ClickHouse этим заданием не очищаются. Для системных логов сохраняется прежний отдельный месячный TTL.
- Root-owned скрипт: `/usr/local/sbin/arm-event-history`; источники: `scripts/maintain-event-history.py`, `ops/event-history/`.
- Служба `arm-event-history.service`, таймер `arm-event-history.timer`. Блокировка не допускает два одновременных запуска этого скрипта. Удаление — синхронная мутация ClickHouse, без изменения схемы/TTL.
- Таймер использует монотонный интервал, а не календарные числа 1/4/7. После повторного включения или перезагрузки первый запуск откладывается на 72 часа. Пропущенные во время выключения интервалы не выполняются залпом.

## Ручной полный экспорт

На сервере:

```sh
sudo /usr/local/sbin/arm-event-history --apply --export-only
```

Команда ничего не удаляет. Архивирует все события до зафиксированного времени, схему и диагностическую копию исторических failed_jobs ID 1–21 до 26.10.2026 (после первой очистки эта часть пуста). Новые failed_jobs автоматически не удаляются и этой исторической выборкой не архивируются.

Каталог `/var/lib/arm-event-history` — root:0700. Формат: `events-YYYYMMDDTHHMMSSZ.tar.gz.age` и квитанция `.json`. Закрытый age-ключ остаётся на ПК, на сервере только публичный recipient `/etc/arm/backup-recipient`. Внутри: `user_actions.sql`, `user_actions.native`, `failed_jobs.json`, `manifest.json` с количеством строк, границей времени и SHA-256 файлов.

Перед упаковкой Native читается отдельным `clickhouse-local` из того же образа, без сети, с ограниченными ресурсами. Сравнивается количество строк. Это проверка формата/читаемости, а не проверка полного восстановления всего приложения.

Для передачи шифротекста создать временную доступную deploy копию через `sudo install -o deploy -g deploy -m 0600 ... /tmp/...age`, затем скачать scp в приватный каталог ПК. Сверить SHA-256 с квитанцией; расшифровать локальным age и проверить внутренние SHA-256. Не извлекать открытые персональные данные в Git/public. После проверки удалить временную передаточную копию. Ручные архивы автоматически не удаляются: переносить нужные на ПК и освобождать сервер вручную.

## Восстановление

1. Приостановить таймер; сохранить текущую историю отдельно.
2. Проверить age-аутентификацию, манифест, хеши и число строк.
3. В отдельном изолированном ClickHouse той же версии создать таблицу из `user_actions.sql`; загрузить `INSERT INTO default.user_actions FORMAT Native` из `user_actions.native`.
4. Сверить количество строк, период и выборки. Не импортировать сразу поверх production: повторный импорт создаёт дубли, схема не содержит уникального ID события.
5. Возврат истории в production согласовать отдельно; режим очистки иначе снова удалит старые события.

Архив failed_jobs — диагностика. Не восстанавливать его в рабочую очередь и не выполнять массовый retry: это может повторно отправить старые уведомления.

## Проверка и отключение

```sh
sudo systemctl status arm-event-history.timer --no-pager
sudo systemctl list-timers arm-event-history.timer --all --no-pager
sudo journalctl -u arm-event-history.service --since '7 days ago' --no-pager
sudo systemctl disable --now arm-event-history.timer
```

Отключение таймера не останавливает уже начавшуюся мутацию и не возвращает удалённые события. Для включения: `sudo systemctl enable --now arm-event-history.timer`. Ошибка службы видна в systemd/journal; отдельного Telegram-алерта для этой службы пока нет. Существующий мониторинг очередей сохранён.
