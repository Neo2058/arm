## Практический тест PostgreSQL

Скрипт: scripts/verify-postgres-backup.py. Job arm-backup-restore-check-20261030,
Result=success, ExecMainStatus=0. Проверка завершилась 30 октября в 18:39 МСК.

Источники:

- /root/arm-hardening-data-20261028/database.dump, 447 958 байт;
- /root/arm-backup-check-20261030T153858Z/postgres.dump, 487 370 байт.

Свежий pg_dump создавался read-only с согласованным snapshot и lock wait 5 секунд.
Контейнер теста использовал image digest рабочего PostgreSQL, network none,
read-only rootfs, cap-drop ALL/no-new-privileges, user postgres, только tmpfs,
без published ports, bind mounts и постоянных volumes. Ограничения: 512 МБ,
0,75 CPU, 128 pids, PGDATA tmpfs 256 МБ. Никаких production secret env в тесте.

Для каждого дампа выполнены pg_restore --list, затем реальный pg_restore с
exit-on-error. В обоих: 89 public tables, 92 migration records, 82 foreign keys,
0 unvalidated foreign keys. Проверены доступность и агрегированные количества
users/documents/work_shifts без вывода содержимого строк.

Restore выполнялся без owners/ACL: исходные роли и права нужно восстанавливать
отдельно по актуальному hardening runbook. Этот тест не проверяет исходные grants,
связь PDF с MinIO, работу всего приложения или восстановление с внешнего хранилища.
Также это не доказательство отсутствия вредоносных изменений в исходных данных.

SHA-256, counts, TOC и журналы — приватно в
/root/arm-backup-check-20261030T153858Z/report.json и соседних файлах.
Каталог root-only, файлы создавались с umask 077. Дамп остаётся локальным.
Тестовый контейнер удалён, отсутствие подтверждено docker ps -a.
После теста arm-app healthy, остальные контейнеры работают, /login и /install 200.
