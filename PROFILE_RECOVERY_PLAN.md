# Профиль и восстановление доступа

План согласован 2026-10-23. Выполняется небольшими этапами.

## Ограничения

- Карусель — каноничное главное меню. Существующие карточки, порядок, изображения,
  размеры, анимации, стрелки и свайпы сохраняются. «Мой профиль» добавляется последней.
- Первый этап: только просмотр собственных данных и переход к существующей привязке Telegram.
- Роли, кадровые данные, пароль и правила доступа на первом этапе не редактируются.
- Производственная выкладка и обновление APK выполняются отдельно.

## Результат первого этапа

- `/account` показывает только текущего пользователя; сохраняет существующие auth/device/barrier проверки.
- Telegram управляется на существующей `/account/telegram`, доступной до прохождения барьеров.
- Новые события ClickHouse на этом этапе не вводились; существующие события привязки сохранены.
- Feature-проверки: 89 тестов / 435 assertions успешно, включая AccountProfileTest, TelegramBotsTest,
  JournalAccessTest, FileProxyTest, NaryadPlanningTest, WebRoutesSplitTest, UserRoleAccessTest.
- Vite production build успешен; проверочные файлы записаны в `/tmp/arm-profile-vite-build`.
  Для выкладки требуется обычная production-сборка фронтенда. Production не обновлялся.
- Проверка в настоящем браузере и на телефоне ещё не выполнена.

### Проверка вручную

1. После обычного входа открыть карусель: прежняя первая карточка и все разделы на месте,
   стрелки, свайпы и переход по центральной карточке работают.
2. Открыть последнюю карточку «Мой профиль», проверить собственные данные и возврат в меню.
3. Проверить страницу на узком экране: секции расположены одна под другой, email переносится.
4. Перейти к привязке Telegram; после привязки вернуться в профиль — статус «Привязан».
5. Без входа `/account` должен переводить на логин; чужие данные через query-параметры недоступны.

## Второй этап — 2026-10-24

Реализован в исходниках. `/reset` и `/start recover` используют существующего бота ключей.
Токен — 64 случайных символа, в БД только SHA-256; срок 10 минут, повторная выдача через минуту
заменяет прежнюю ссылку. Выпуск и погашение берут блокировку пользователя в транзакции и повторно
проверяют запись. Внешний ключ на конкретную привязку Telegram не позволяет использовать старую
ссылку после отвязки и повторной привязки того же Telegram ID.

Ссылка строится из HTTPS APP_URL, без доверия к Host запроса, токен передаётся через fragment.
GET ничего не меняет; POST защищён CSRF и throttle. Ошибки не сохраняют токен/пароль в old input.
После сброса меняется remember token, удаляются Sanctum-токены и сессии пользователя при database driver.
Для остальных session drivers прежний отпечаток пароля отклоняется AuthenticateSession на следующем web-запросе.
В стандартном Laravel 12 SessionGuard этот отпечаток записывается уже при входе.

Бот алёртов получает уведомление об успешном сбросе только с ID пользователя, без ссылки и пароля.
События ClickHouse согласованы пользователем 2026-10-24: `password_reset_requested` после выдачи
токена и `password_reset_completed` после успешной смены пароля. Используется ClickHouseService,
очередь analytics; resource_id/actor — пользователь, details содержит только channel=telegram.
Схема ClickHouse не меняется, секреты не записываются. Ошибка очереди не отменяет выполненный сброс.
Месячный барьер, одобренные устройства и роли не сбрасываются и не обходятся.

Проверки: 98 feature-тестов / 497 assertions, Vite build и Android Metro export успешны.
Тесты используют SQLite; реальные параллельные транзакции PostgreSQL и проход через Telegram/браузер
ещё требуется проверить. Production и установщики не обновлялись.

### Выкладка и проверка

1. Проверить HTTPS `APP_URL` (для текущего production — адрес с www), существующие настройки бота,
   webhook secret и worker `database/notifications`. Новые токены BotFather не нужны.
2. После резервной копии БД выложить код и выполнить в контейнере:
   `php artisan migrate --force`, затем пересобрать конфигурационный/route cache по принятому процессу.
   Миграция добавляет `telegram_password_resets`; без неё команда /reset не заработает.
3. Выполнить production-сборку веб-фронтенда, чтобы появилась карточка профиля в карусели.
4. В BotFather у существующего бота ключей через `/setcommands` добавить
   `reset - Восстановить пароль`, сохранив существующие команды.
   Команда работает и без меню; webhook переустанавливать не требуется.
5. На тестовом аккаунте заранее привязать Telegram. Открыть «Забыли пароль?» → бот → /reset,
   открыть полную ссылку во внешнем браузере, ввести новый пароль. Проверить уведомление,
   вход с новым паролем и отказ старых веб-сессий/мобильного токена.
6. Проверить две одновременные отправки формы на PostgreSQL: только одна должна изменить пароль.
   Отдельно проверить истечение 10 минут и отвязку Telegram до погашения.
7. Для кнопки «Забыли пароль?» на Android требуется новая сборка APK и отдельная публикация.
   На старом APK можно использовать /reset в боте, затем войти с новым паролем.

При откате функционала убрать точки входа до отката миграции; не удалять таблицу при работающем /reset.
Ссылки истекают автоматически; старые строки заменяются следующей выдачей.
