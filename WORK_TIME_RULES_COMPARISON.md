а не отдельные константы в вебе и APK. Инициализировать недостающие значения явно,
не перезаписывая существующие поля полным импортом NRDPAR.

## Два отдельных алгоритма ночных

### Отдельная смена: CNTSMEN.PRG, 621–695

1. chas — полная продолжительность; lin1 = chas − chasr1 (резерв отделяется от линии,
   но остаётся оплачиваемым временем).
2. Определяется t_noch по времени и коду смены; «1» обрабатывается отдельно.
3. При t_noch >= chas/2: t_noch = chas; весь резерв становится ночным;
   вечерний резерв обнуляется. Вечерняя доплата смены при этом не начисляется.
4. Ночь линии = t_noch − ночной резерв, вечер линии = t_vech − вечерний резерв.
5. Если сумма ночных/вечерних линии и резерва больше chas, оригинал требует ручной корректировки.

Это дополнительная логика, ранее не учтённая при чтении одного UCHET.rs_noch.
Граница >=50% включительна. Начальные ночные часы оригинал вычисляет процедурными ветвями,
а не универсальной функцией пересечения: перед заменой на геометрическое пересечение
нужны отдельные эталонные случаи для смены «1», раннего начала, резерва и перехода суток.

### Связка: UCHET.PRG, 2368–2371, 3453–3530

Только при NR_ONOCH=+ перед формированием ЛС выбираются NR_NSM1/NR_NSM2 и следующая
запись того же табельного на следующий день, LEFT(smena,1)=1.
Сумма ночных частей сравнивается с половиной суммы chas обеих записей.
При достижении порога vse_noch вызывается для обеих записей:
Noch1=lin1, Nochr1=chasr1, вечерние=0; аналогично для второго работника через CHAS2.
Перерыв между частями не становится оплачиваемыми рабочими часами автоматически:
в знаменателе сумма chas, а не время от начала первой до окончания второй записи.

Не подменять этим правилом любую одиночную смену через полночь и не применять к 5+
только потому, что этот код присутствует в более строгом PLANIR Laravel.
Ночные коды планировочного контроля и правила оплаты — разные настройки.

## Отдых

Laravel `requiredIntervalHours` соответствует основным формулам PLANIR.r_interval/post_vih:

- Без выходного: max(12, 2 × D).
- После n выходных в formula: max(18 + 24n, 2 × D + 24n).
- При fixed: interval_hours / rest_day_hours / two_rest_days_hours.

D берётся из предыдущего дежурства. Для продолжения «с ночи» Laravel previousDutyHours
суммирует часы с предшествующей ночной частью. Считать фактический интервал от окончания
последней части до следующего начала. Работать с соседними месяцами и всей необходимой
цепочкой выходных, а не только записями выбранного месяца.

Примеры formula: D=8, без выходного →16 ч; с одним →42 ч; с двумя →66 ч.
D=10: без выходного →20 ч; с одним →44 ч; с двумя →68 ч.
Следовательно, безусловные 42/66 неверны для formula при длительном дежурстве.
Планировочные запреты сохраняются. Фактическую уже состоявшуюся смену записываем
с предупреждением о нарушении, не выдавая её за разрешённое назначение.

## Оплачиваемые перерывы и существующий WorkShift

Владелец подтвердил оплату всех перерывов. Они входят в оплачиваемую длительность смены.
Периоды между самостоятельными частями/сменами нельзя автоматически считать таким перерывом.
Нужно хранить явную принадлежность оплачиваемого времени виду работы (линия/резерв/поверхность).

Текущие `WorkShift::booted` и `Payroll/ShiftCalculator` вычитают break_duration;
модель начисляет 450 руб./ч, PayrollRules задаёт 450 и премию 32%.
Контроллер `Api/WorkShiftController` сохраняет через updateOrCreate(user_id, shift_date):
несколько смен за день заменяют друг друга. Валидация не запрещает отрицательный перерыв
и не требует конец позже начала. Это реальные препятствия для нового табеля.

Миграция должна сохранять исходные записи/старые итоги; новые смены получают явную
версию правил с оплачиваемыми перерывами. Не пересчитывать историю от одного просмотра.
Расчёт total_minutes/estimated_earnings должен остаться единым в saving-hook через общий сервис,
preview должен вызывать тот же расчёт. Отвлечения продолжают использовать свой каталог.

## Округление

`UCHET.sub_vr` (3535–3550) и `CNTSMEN.sub_vr` читают NR_ROUND:
«-» → ROUND(delta1,2), иначе ROUND(delta1,1). В копии «+»: одна десятичная цифра.
Например 8 ч 20 мин — 500 точных минут, 8,33 часа в выводе до сотых и 8,3 часа
при совместимом округлении до десятых. 5.30 в полях FoxTime означает 05:30.
Не превращать округлённые часы обратно в фактические минуты и не округлять каждый
сегмент произвольно: точки округления должны соответствовать исходным операциям.

night+continuation по обе стороны порога, отсутствие пары/другой табельный/разрыв даты,
конец месяца, исторические настройки, второй работник, NR_ROUND и ручные корректировки.
