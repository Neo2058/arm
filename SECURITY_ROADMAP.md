Лимиты считают все запросы, включая успешные: login — 5/мин на аккаунт и 30/мин на IP
(общие web/mobile); barrier — 10/час на пользователя и 30/мин на IP; device registration — 5/час
на ключ стандартного Laravel throttle для авторизованного пользователя. Filament имеет собственный limiter входа.

Короткий месячный ключ остаётся слабым общим секретом. MFA для администраторов и замена барьера —
отдельный пакет после проверки пользовательского процесса; limiter не делает ключ сильным.
В production limiter должен использовать общий Redis/cache, а не process-local array.

Совместимость: старые вкладки могут прислать score/total_questions, но сервер их игнорирует и вычисляет значения

новые события и схема ClickHouse не добавляются.

## Ручная выкладка первого пакета (этапы 1–2)

Это инструкция для оператора production, не отметка о выполнении. Автоматического деплоя нет.

1. Записать текущий SHA (`git rev-parse HEAD`) и проверить чистоту checkout (`git status --short`).
   Не применять git reset --hard к checkout с неизвестными изменениями. Сохранить защищённую копию .env и backup БД.
2. На отдельном checkout/release проверить выбранный commit и выполнить тесты. Docker команды ниже
   предполагают существующий production Compose; если на сервере используется иной файл, адаптировать явно.
3. В согласованное окно включить maintenance: `docker compose -f docker-compose.prod.yml exec app php artisan down`.
4. Обновить checkout до проверенного commit. Для этапов 1–2 миграции, новые env и frontend build не требуются.
5. Выполнить `docker compose -f docker-compose.prod.yml exec app php artisan optimize:clear`,
   перезапустить app и восстановить кеш после перезапуска:
   `docker compose -f docker-compose.prod.yml restart app`, затем
   `docker compose -f docker-compose.prod.yml exec app php artisan optimize`.
   Entrypoint очищает кеш при старте; optimize до restart не сохраняет его.
6. Перезапустить существующие queue workers, если они работают вне app; проверить их фактический способ запуска.
7. Выполнить `docker compose -f docker-compose.prod.yml exec app php artisan up`.
8. Проверить login/logout, сохранение/загрузку файла в Filament, Livewire без 419 с корректным токеном,
   блокировку тестового аккаунта и Bearer API, документы, журнал и наряд. Следить за ошибками 419/403/500.
9. При регрессии вернуть checkout к записанному предыдущему release в maintenance, очистить кеш,
   перезапустить app и workers, восстановить кеш, выполнить smoke и только затем снять maintenance.
   Откат возвращает старые риски безопасности: зафиксировать причину и ограничить внешний доступ на время исправления.
