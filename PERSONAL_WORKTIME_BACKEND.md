## Данные и совместимость

Миграция `2026_10_27_100000_version_personal_work_shifts` расширяет существующую work_shifts:
calculation_version (default 1), operation_id/hash, shift_code, segments,
calculation_snapshot и calculation_result. Суммы и минуты старых строк не обновляются.
Отдельная work_time_month_settings хранит личные ставки/проценты пользователя на первое число месяца;
это настройки личного WorkShift, а не параллельный официальный лицевой счёт.
Ключ user_id/month уникален; внутренние записывающие вызовы должны передавать первое число месяца.

Старый WorkShiftController читает/сохраняет только v1. Он не видит и не перезаписывает v2,
но старое поведение «одна запись на дату» пока сохраняется для старого интерфейса.
Следующий интерфейс обязан работать через новый сервис, а не расширять старый updateOrCreate по дате.

## Общие сервисы

- PersonalWorkTimeSettings: снимок подтверждённых ставок, временных окон и правил отдыха.
  Ставки в копейках: линия 57348, резерв 55300, поверхность 51204; вечер 20%, ночь 40%.
  Личные помесячные overrides ограничены этими пятью денежными параметрами.
  Временные окна берутся из planir либо из подтверждённых NRDPAR 16/22/06;
  округление по исследованной копии — 1 десятичный знак часа, таймзона Europe/Moscow.
  НСИ не обновляется при preview/create.
- PersonalWorkTimeCalculator: считает точные минуты, распределение по видам работы,
  фактические и зачтённые ночные, вечерние, базовую оплату и две доплаты.
  Денежные компоненты вычисляются в целых копейках с округлением half-up.
  Часы для денежного расчёта округляются по видам работы после суммирования минут;
  точные минуты не заменяются результатом этого округления.
- PersonalWorkShiftService: preview без записи и create с UUID, проверкой активности,
  транзакцией и блокировкой строки пользователя для сериализации параллельных созданий.
  Повтор UUID с теми же входными данными возвращает прежнюю запись со старым снимком;
  иные данные под тем же UUID дают 409. Пересечения, включая v1, отклоняются;
  смежные непересекающиеся смены на одной дате разрешены.
- WorkShift::saving: для v2 вызывает тот же калькулятор, сохраняет precomputed поля;
  существующий снимок ставок не меняется от последующих изменений настроек.
  Переход версии 1↔2 и смена владельца v2 запрещены. Перенос в другой месяц требует
  новой записи/отдельной будущей операции переноса, без подмены исторического снимка.

Событие только существующее work_shift.saved после COMMIT, без новых action_type.

## Контракт времени

Вход сервиса — локальное московское время `YYYY-MM-DD HH:mm` (или T вместо пробела,
допустимы секунды :00). ISO-строки с Z/offset пока не принимаются: будущие клиенты должны
явно преобразовать своё представление в этот контракт. Иначе Laravel с timezone=UTC может
потерять исходный offset при сохранении datetime без таймзоны.
shift_date совпадает с московской датой начала. Конец содержит полную дату и позже начала.

Каждый участок имеет kind=line/reserve/surface, started_at, ended_at. Участки идут по порядку
и полностью покрывают смену без пробелов и пересечений. При отсутствии участков вся смена — линия.
break_duration — справочные оплачиваемые минуты, не вычет из покрытия. Он не может превышать
длительность смены. Тариф оплачиваемого перерыва определяется покрывающим его участком.
Технические пределы входа: 128 участков, 7 суток на одну запись; это не разрешённая норма смены.

## Что нельзя выдавать за завершённый расчёт

calculation_result.calculation_complete всегда false. estimated_earnings v2 — только subtotal
линии/резерва/поверхности с вечерней и ночной доплатами, не зарплата после удержаний.
В результате перечислены pending; новый UI обязан показать незавершённость прогноза.

Одиночная классификация сейчас использует пересечение окон плюс порог >=50% после округления.
Это проверенная основа, но не полный перенос процедурных ветвей CNTSMEN для всех кодов смен,
раннего начала и длинного дежурства. Спецпересчёт пары ночь–с ночи UCHET ещё не применяется;
для кодов 1/3+/4+ он дополнительно отмечается в pending.
Не обещать совпадение полного сентябрьского квитка на этой стадии.

rest() переиспользует public PlanirRulesService::requiredIntervalHours без копирования формулы.
Вызывающая будущая месячная сводка должна определить число выходных, предыдущее дежурство
и обе части связки. Сейчас функция принимает эти параметры явно и возвращает фактические/
необходимые минуты и нарушение; сам create не запрещает запись состоявшейся смены из-за отдыха.
Автоматический подбор цепочки и вывод предупреждений в UI — следующий блок.

Редактирование/удаление смен и API изменения помесячных настроек ещё не открыты.
Для редактирования нужен отдельный сервис с блокировкой, проверкой владельца, пересечений,
версией записи и идемпотентностью; прямой model.save не заменяет эти проверки.

- Новый PersonalWorkTimeTest: 16 тестов, 65 assertions, также прошёл на изолированном PostgreSQL 17.
- Проверены preview=save, оплачиваемые перерывы, ставки трёх видов, 16/22/06,
  включительная граница половины ночных, месяц/полночь, точные минуты и округление,
  idempotency, владельцы, блокировка неактивного, ошибки входа и защита v2 от старого API.
- Отдельный тест down/up на тестовой БД подтверждает: миграция не меняет старые ручные
  total_minutes=123 и estimated_earnings=987.65.
- Реальные гонки: tests/Support/worktime-concurrency.php, только PostgreSQL arm_worktime_test_*
  на локальном Unix socket /tmp/arm-worktime-pg.*; одинаковый UUID → одна запись,
  разные UUID с пересечением → один успех и 422, один UUID с разными данными → успех и 409.
- Одноразовый PostgreSQL остановлен после проверок; production не использовался.

## Следующий шаг и будущая выкладка

Завершить классификацию/пересчёт ночных связок и месячную сводку с отдыхом; добавить
защищённые операции редактирования и настройки, затем подключить веб и APK к одному API.
Неподтверждённые базы премии/удержаний оставлять ручными/неполными.

Перед будущей выкладкой сохранить backup. Сначала применить миграцию, затем включить код,
который обращается к calculation_version. После появления данных v2 не откатывать миграцию down:
это удаляет снимки и участки. Для отката поведения использовать совместимое исправление кода.
В этой итерации нет push/deploy и сборки APK. Отдельные изменения картотеки/профиля сохранены.
