# Локальная часть АРМ: ARM-NRD

Добавлено по указанию владельца 09.11.2026. Программа входит в общий продукт АРМ, показывается отдельным рабочим местом, рядом с вебом и Android.

Путь исходников: `/Users/vyacheslavandreevich/.gemini/antigravity/scratch/arm-nrd`.
Исполняемый файл: `build/arm_nrd`, обнаружен Mach-O arm64. Изучены `OPERATIONAL_ROADMAP.md`, `CMakeLists.txt`, `src/main.cpp`, начало `MainWindow.cpp`, точки обмена в `NaryadSyncClient.cpp`, `scripts/api_server.py` и места подключения `PlanningGridModel.cpp`.

## Что включить в демонстрацию

- Локальное рабочее место планирования и учёта локомотивных бригад: месячная сетка, выбор периода, бригад/колонн, поиск сотрудника и итоговые часы.
- Картотека, карточка машиниста, календарь, разбивки, явки/окончания и инспектор смены.
- Контроль отдыха и ограничений, поиск незакрытых смен, подбор замены и закрытие наряда.
- Больничные, отпуска, учёба и управление отвлечениями; переход на новый месяц.
- Печатный суточный наряд и локальные подстройки.
- Связь с серверным контуром: заявка сотрудника → обмен через API → рассмотрение в локальном рабочем месте → результат для сотрудника. Последовательность передачи/подтверждения в обоих направлениях проверить на учебном стенде до записи.

Стек по исходникам: C++20/Qt 6, libpq/PostgreSQL, Redis; Python API. Это отдельный настольный клиент, не Android и не страница браузера.

## Подтверждение обмена и границы

В C++ найден клиент получения серверных подстроек через `api/mobile/podstroiki/sync-for-naryad` и импорт данных. В локальном Python API найдены GET/POST/DELETE для подстроек и GET лимитов. Само наличие входящих/исходящих операций не доказывает полную синхронизацию всех данных, устойчивость к разрыву связи, отсутствие конфликтов и сквозную приёмку. Все стрелки схемы должны получить подтверждённый учебный сценарий. Не объявлять полную offline-работу и автоматическую синхронизацию всех справочников без проверки.

Дорожная карта desktop заявляет базовые оперативные блоки готовыми, но отдельно оставляет в планах часть учёта второго лица, фактических маршрутных листов и дополнительных отчётов. Статусы сверять с текущим кодом, не переносить готовность веб-учёта на desktop автоматически.

## Условия съёмки

`MainWindow` загружает данные сразу при старте; в `PlanningGridModel.cpp` найдены прямые подключения к локальной БД и Redis. Поэтому существующий бинарник пока не запускался. Он может открыть рабочие персональные данные. Не менять рабочую БД, конфигурацию, подключения или существующую программу ради кадров.

Перед съёмкой подготовить отдельную учебную БД/Redis и изолированный экземпляр приложения с явно заданными адресами. Проверить все прямые подключения, не полагаться только на смену HOME или PGDATABASE: часть параметров задаётся непосредственно в исходниках. При необходимости собрать отдельную demo-копию вне рабочего дерева, сохранив функции и проверки. Не запускать локальный API на 0.0.0.0 для презентации; доступ должен быть только loopback/изолированная сеть. Не переносить боевые токены между стендами.

Снять реальное окно Qt с учебными сотрудниками, затем сквозной обмен через изолированный API. Если возможности этого обмена окажутся частичными, показать подтверждённую часть и подписать остаток как развитие.
