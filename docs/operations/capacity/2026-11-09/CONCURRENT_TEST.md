## Методика

Генератор `tools/capacity/concurrent_read.py` переиспользует проверенные targets, чтение метрик и guard из `read_smoke.py`. Продуктовый код и конфигурация production не меняются. Токены только в приватном временном файле, в Git не попадают. Для показателей используется временный loopback SSH-туннель к экспортеру; внешние порты не открываются.

Перед измерением проверяются все 25 сочетаний аккаунт/раздел. После этого три ступени по 90 секунд, между ними и после последней — 20 секунд наблюдения. На каждой ступени barrier синхронизирует отправку 2, 3 или 5 запросов с отдельных аккаунтов/соединений. Группа полностью завершается до следующей; промежуток между началами групп не менее `размер группы × 1,1 секунды`. Задержанные группы не отправляются залпом для наверстывания графика.

Маршруты: личный месяц, категории документов, список нарядов, темы обучения и inbox чата. У каждого аккаунта собственный токен; повторное использование одной учётной записи для всех запросов и обход проверок доступа отсутствуют. В измеряемых группах аккаунты/маршруты назначаются детерминированно; один аккаунт не получает два запроса одновременно. Барьер обеспечивает клиентский параллелизм; точное одновременное выполнение в FPM/БД этими метриками не доказывается.

Остановка: любой невалидный ответ, клиентская задержка измеряемого запроса >1 с, новая 5xx, неуспешное задание, проблема мониторинга или ресурсный порог из предыдущего этапа. После остановки более высокая ступень не запускается. Первоначальный прогрев проверяет содержимое ответов отдельно; время открытия соединений не используется для объявления серверной ёмкости.

PDF, MinIO-передача, заполненные финансовые расчёты и переписка не входят в этот прогон. Число элементов и ответы в исходных тестовых профилях пустые, кроме доступных общих списков. Результат следует трактовать только для этого профиля.

Машинный отчёт: `concurrent-read.json`. Личные данные, ответы API, заголовки авторизации и токены не сохраняются. После теста отдельная транзакция удаляет только аккаунты с меткой этого запуска после проверки их роли, имён и отсутствия смен. Новые рабочие записи не очищаются вместе с тестом.
