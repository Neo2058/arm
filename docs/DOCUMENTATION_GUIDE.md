# Ведение документации

## Структура и навигация

Начинать с [общего оглавления](README.md). Тематические документы размещать в соответствующем разделе `docs/`, отчёты о выпусках — в `releases/`. В корне остаются README проекта и AGENTS.md; правила мобильной разработки — рядом с мобильным кодом.

При добавлении документа обновлять оглавление. Использовать относительные ссылки, сохранять связанные изображения и инструменты рядом с существующими презентациями. При переносе проверять как Markdown-ссылки, так и пути в командах и генераторах. Рабочий каталог команд по умолчанию — корень репозитория, если явно не указано другое.

## Проверка ссылок

Из корня проекта:

```bash
python3 tools/docs/check_links.py
```

Проверка охватывает относительные Markdown-ссылки и изображения, а также локальные HTML `src` в Markdown. Внешние URL, ссылки на временные или закрытые локальные каталоги и якоря требуют отдельной проверки; сеть инструмент не использует.
