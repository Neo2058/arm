# Каталог документов: подпапки, дубли и редакции

12.11.2026. Порядок утверждён владельцем. Файлы хранить до особой отметки о выводе из действия; автоматического удаления по возрасту нет. Отметка о выводе — разрешение перейти к проверке удаления, а не немедленное удаление без проверки ссылок и истории. Срок «45 лет» автоматически ко всем файлам не применяется.

## Этапы

1. [x] Код первого этапа (локально, без выпуска): вложенные разделы под существующими категориями, веб/APK, поиск по названию/номеру/году. Проверка точных дублей по SHA-256. Существующие ID документов, роли и подписи сохраняются.
2. [x] Код подготовлен локально: семейство документа и отдельные редакции, действующая версия и дата введения. Новая редакция не наследует старые отметки; связанные тесты/ссылки на страницы требуют проверки. Год — реквизит, а не единственный идентификатор редакции.
3. [x] Код подготовлен локально: явный вывод из действия с датой/основанием, исключение из пользовательской выдачи; административный архив и история ознакомления остаются.
4. [ ] Отдельная проверяемая очистка выведенных файлов: зависимости, нужность исторического оригинала, общие ссылки на объект, резервные копии. Без отметки вывода объект не удаляется. MinIO, его настройки и существующие объекты не менять попутно.

## Границы первого этапа

Категории верхнего уровня и каноническая карусель сохраняются. Подпапки не дают дополнительных прав: видимость каждого документа определяется прежними ролями. Пустые/полностью закрытые ветви не выдаются пользователям. Старые APK получают прежний плоский список; новые клиенты используют дополнительные данные пути.

Год/номер/похожее название помогают искать возможный дубль, но сами по себе не доказывают идентичность. SHA-256 выявляет только одинаковые байты; сканирование того же документа иначе даст другой хеш. Исторические файлы требуют чтения и индексации до полного покрытия проверкой. Файлы не удалять для устранения обнаруженного дубля автоматически.

Новые ClickHouse-события согласованы отдельно. Перед выкладкой проверить миграцию и права runtime-роли. Замена файла у прежнего document_id сохраняет старые подписи в текущей модели, поэтому полноценная смена редакции требует этапа 2.

## Состояние после первой итерации

Код первого этапа реализован локально, **не опубликован**. Production и доступный APK остаются 1.1.9. Созданы DocumentFolder/Filament CRUD, реквизиты документа, совместимый API, дерево и поиск веб/APK, предупреждение о похожих карточках, проверка SHA-256 до сохранения нового объекта и повторная проверка перед записью карточки. Публикации сериализуются advisory lock в PostgreSQL. События `document_folder.saved` и `document.catalog_saved` отдельно одобрены владельцем 12.11.2026.

До завершения редакций обычные удаление карточек и замена оригинала в форме отключены. Метаданные/размещение редактируются. Папки можно переименовать; их родитель и основная категория фиксируются при создании (защита от циклов, в том числе конкурентных). Новая иерархия относится к каталогу документов; отдельные папки росписей пока остаются прежними. Один документ можно включить в инструктаж через существующую связь, не загружая копию.

### Подготовка выкладки (ещё не выполнена)

1. Свежая резервная копия и проверка восстановления; проверить изменения только этого выпуска.
2. Проверить и применить **только** `2026_11_12_160000_add_document_folders.php` администратором БД; обеспечить runtime-роли DML на document_folders и последовательность. Старые строки остаются с NULL в добавочных полях, без перемещения файлов.
3. `php artisan documents:index-hashes` показывает покрытие без записи. `php artisan documents:index-hashes --apply` читает старые объекты и заполняет SHA-256. При недоступном файле операция завершается ошибкой; сначала восстановить доступ, не удалять карточку для обхода. Имеющиеся дубли остаются, команда считает группы.
4. Доставить код/веб-ресурсы штатным read-only deployment-процессом; API совместим со старым APK. Новый APK требует увеличения versionCode, прежней подписи и установки/запуска. Не публиковать новый бинарь под прежним versionCode.
5. Ручная приёмка: создать подпапки, переместить карточку, найти по номеру/году, проверить роли и росписи. Точное повторное добавление файла блокируется, другое содержимое под тем же исходным именем не перезаписывает оригинал.

Нет автоматического удаления ни рабочих, ни временно оставшихся объектов. При гонке двух загрузок запись дубля блокируется, но уже загруженный проигравшим запросом объект может остаться без карточки. Его нельзя считать разрешённым к удалению по одному возрасту; учёт таких объектов/контролируемая очистка — этап 4. До смены редакции нельзя обещать новое требование росписи при простом редактировании карточки.

## Проверки первой итерации

14 тестов DocumentCatalogTest: формы Filament, дубль до записи нового объекта, одинаковые исходные имена без перезаписи, индексация без удаления, права, путь веб/APK, сохранность росписей, глубина и циклы, недоступный оригинал. Общий набор с обязательными проверками доступа — 99 тестов / 509 assertions; 2 Node-теста общего дерева/поиска. Веб build, Android JS export и проверка ссылок документации прошли. Нативный APK этого этапа не собирался и не публиковался; PostgreSQL-конкурентность advisory lock ещё требует интеграционной приёмки, SQLite-тесты её не доказывают.
