## Реализация периодов

Существующая таблица work_shifts, версия 2, type=deviation; добавочная миграция
`2026_10_27_170000_add_personal_absences_to_work_shifts` добавляет absence_kind и absence_end.
Категории sick/leave/study, обе даты включительны, до 366 дней в одной записи (технический предел).
Сервер выводит интервал [начало 00:00, следующий день после окончания 00:00) в московском времени.
Отдельная таблица учёта и фиктивные нулевые тарифы в deviations_catalog не создаются.

PersonalWorkAbsenceCalculator вызывается тем же WorkShift::saving. Минуты работы и
сохраняемый subtotal равны 0, но payment_status=not_calculated: это **не утверждение
об отсутствии оплаты**. В интерфейсе сумма периода не показывается как 0 ₽.
Официальные ЛС/PLANIR и формулы оплаты рабочих смен не менялись.

Тот же /shifts API принимает type=deviation, absence_kind, shift_date, absence_end.
Владелец из сессии/токена, блокировка User, expected_revision, прежняя UUID-квитанция.
Записи разных типов не преобразуются друг в друга. Проверка пересечений работает в обе
стороны и для старых записей без времени; старый веб-календарь также не может писать
внутрь нового периода. Существующее событие work_shift.saved, без новых медицинских деталей.

GET month возвращает absences отдельно с days_in_month и исходными границами периода,
включая периоды, начавшиеся раньше выбранного месяца. Рабочие часы/деньги не увеличиваются.
Больничный/отпуск/учёба между дежурствами не считаются подтверждёнными выходными или
обычным междусменным отдыхом: оценка нормы в таком промежутке не определена явно.

Веб и Android: кнопка «Больничный / отпуск / учёба», общая форма, календарь, список и
редактор; конфликт требует сверки, неопределённый ответ повторяется с тем же запросом.

## Реализация PDF

Старый просмотр настоящего PDF создавал 81 canvas, 317 932 776 байт пикселей.
Новый рисует одну выбранную страницу; потолок — 2 млн пикселей (8 МБ), старый рендер
отменяется, ресурсы страницы освобождаются. Первая/последняя страницы и быстрые переходы
проверены на настоящем PDF в локальном Chrome.

DocumentViewScreen загружает небольшую HTML-оболочку, передаёт base64 порциями 64 КиБ
по подтверждению WebView, освобождает исходные данные после передачи. Таким образом
многомегабайтный документ не становится многомегабайтным source.html.
Есть номер страницы, повтор открытия, обработка остановки renderer и отмена запроса.
Signed-route, проверки ролей, isEvalSupported=false, блокировки скачивания/печати/снимков
и приватный режим не ослаблены. PDF и его содержимое не записываются в клиентские черновики.

Production-файл и его настоящий подписанный HTTPS-поток побайтно совпали.
В Android-стенде отдельно обнаружен UnknownHostException при загрузке PDF.js: эмулятор
не разрешал внешний домен. Для повторяемого теста используется только локальный стенд
через adb reverse; разрешение HTTP/точка входа меняются только в приватной тестовой сборке
и восстанавливаются try/finally. Финальный APK должен содержать production HTTPS API,
не содержать тестовых файлов и не разрешать cleartext HTTP.
