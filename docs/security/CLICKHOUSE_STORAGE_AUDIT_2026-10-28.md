## Предлагаемый отдельный этап, требует согласования удаления

1. Сохранить DDL/config, перечень partitions и выбранную историю вне сервера,
   если старые технические логи нужны для расследования. Ничего не удалять до
   согласования границы и ценности старой истории.
2. Сохранить весь октябрь: он включает период недавней атаки. После разрешения
   убрать только июнь–сентябрь из пяти перечисленных system-таблиц штатными
   DROP PARTITION, по одной операции с контролем нагрузки/свободного места.
   Не удалять файлы volumes вручную; не выполнять TRUNCATE всей system или приложения.
3. Настроить ограниченное хранение через поддерживаемую конфигурацию system logs,
   например 30 дней, с учётом расследования и будущего внешнего архива.
   Применение TTL к существующим данным может запустить тяжёлые merges;
   не материализовать массово и не выполнять OPTIMIZE FINAL на загруженном сервере.
4. Проверить необходимость постоянно включённого профилирования trace_log и
   уровень text_log; уменьшать шум отдельно от аудита безопасности.
5. default.user_actions и прочие операционные/аналитические данные не очищать
   в рамках этого пакета. Изменения событий/схемы аналитики согласовывать отдельно.
6. Проверить вставку аналитики, заполнение диска и новые данные после изменения;
   затем вернуться к плану внешней резервной копии.

Ожидаемое освобождение при согласованном удалении только июня–сентября:
около 24 GiB. Это оценка активных частей, а не гарантия точного изменения df.

## Завершение после обрыва связи — 29 октября 2026

При расширении TTL на дополнительные системные логи возникла несовместимость:
базовая конфигурация OpenTelemetry содержит явный engine, с которым отдельный
элемент ttl запрещён. Проверка колонок сама по себе этого не обнаруживает.
ClickHouse ушёл в цикл перезапусков, а команда временного восстановления до
обрыва связи не применилась. Веб продолжал отвечать, но нельзя считать аналитику
за этот промежуток полной: ClickHouseService предупреждает об ошибке вставки,
а не гарантирует последующий повтор всех событий.

Исправление: для OpenTelemetry сохранены исходные PARTITION BY/ORDER BY,
TTL finish_date + INTERVAL 1 MONTH DELETE помещён внутрь engine с replace.
У прочих 21 журналов используется отдельный ttl по event_date.
После загрузки исправленного файла ClickHouse восстановился; повторные проверки
подтвердили стабильный started_at/счётчик перезапусков и месячный TTL всех 22 таблиц.

Проверено после восстановления:
- 1117 строк user_actions, контрольная сумма 5171956077125634413.
- Приложение читает ClickHouse и выполняет INSERT ... SELECT ... WHERE 0
  своими credentials: проверено право вставки без новых тестовых событий.
- В пяти очищенных таблицах суммарно 0 строк в разделах июня–сентября.
  Могут оставаться маленькие нулевые части-метки удаления; повторная очистка не нужна.
- Нет незавершённых mutations и переименованных копий system-таблиц вида *_0.
- HTTPS /login = 200; диск около 28G занят, 47G свободно, 38% (округление df).

Повторных удалений данных после возобновления не выполнялось. Будущие изменения
логирования проверять с учётом унаследованных engine, не только наличия колонок/TTL.
