# Росписи по инструктажам — веб и Android

12.11.2026. Опубликовано в Android 1.1.8; результаты публикации — в [акте выпуска 1.1.8](../releases/instruction-signatures-1.1.8.md).

## Сценарий

Документы → «Росписи», либо Профиль → «Инструктажи · росписи». Показаны активные категории и документы, доступные по действующей роли. super_admin включён через существующий `canAccessByRoles`, отдельная колонна не требуется.

Документ открывается в существующем защищённом просмотрщике, тест — существующим QuizPlay. Тест рекомендован, как в текущем веб-сценарии; успешное прохождение не является серверным условием подписи. Ознакомление подтверждается отдельной кнопкой и диалогом «Я ознакомился». Открытие файла само по себе не создаёт отметку. Списки показывают собственные дату и статус, общий счётчик.

Это первый этап — собственные росписи. Новый мобильный экран инструкторской статистики/проверки росписей этим выпуском не добавляется; существующий веб-контроль остаётся. Формуляр и проверка записей формуляра — другой раздел.

## Общие данные и защита

`InstructionSignatures` обслуживает GET/POST мобильного API и веб `/rosisi`. Одна таблица `user_instruction_signatures`, без новых миграций.

- GET `/api/mobile/instructions`: только активные категории, разрешённые документы, собственные отметки, доступный активный quiz_id. Ответ private/no-store. Не возвращает MinIO URL или содержимое чужих отметок.
- POST `/api/mobile/instructions/{document}/sign`: `confirmed=true`, notes опционально до 2000 символов (APK notes не запрашивает). Автор определяется из Sanctum, ID от клиента не используется. Мутации 20/min, active user, monitor-token запрещён.
- Проверяются категория, роль и наличие файла для первой отметки. Транзакция/блокировка пользователя и уникальный индекс user/document обеспечивают один результат. Document берётся shared lock, чтобы чтения разных сотрудников не блокировали друг друга. Повтор возвращает первую дату без обновления и повторного аудита; отдельная таблица UUID-квитанций для этого естественного ключа не нужна.
- Существующее событие `instruction_signed`, после commit, только ID документа/пользователя; ни notes, ни название не передаются новым сервисом. Новых ClickHouse-событий/схем нет.
- Подтверждение сохраняется в private FileSystem `instruction-signatures`, scope API URL + user ID, до запроса. Повторы только вручную. Неопределённый ответ нельзя отбросить; 403/404/422 разрешают закрыть отклонённый запрос. Перевход сохраняет; явный выход удаляет данные и блокирует позднее сохранение старой сессии.

Веб теперь использует те же проверки роли/активности категории, требует именованный флаг confirmed и не меняет первую дату при повторе. Убран ложный текст «прошёл тест» из декларации: сервер этого не проверяет. Старые уже открытые формы до обновления могут потребовать обновить страницу, поскольку раньше checkbox не отправлял именованное значение.

## Ограничение редакций

Это существующая модель одной отметки на document_id, не криптографическая подпись содержимого и не архив подписанных редакций. Замена файла у прежнего document_id не создаёт новое требование ознакомления. Когда необходимо новое ознакомление с редакцией, публиковать новый Document с новым ID; отдельное версионирование подписей требует самостоятельного проекта. Существующие даты/подписи автоматически не обнуляются.

## Проверить на телефоне

1. Под super_admin и машинистом открыть росписи, документ и тест; вернуться к списку.
2. Подтвердить ознакомление и сверить статус/дату в вебе.
3. Повтор после потерянного ответа и перезапуска не меняет дату и не создаёт дубль.
4. Документ другой роли, неактивная категория и отсутствующий файл не допускают первую подпись.
5. Перевход сохраняет ожидающее подтверждение; выход очищает; другой аккаунт его не получает.

MinIO, его конфигурация и объекты, формулы и каноническая карусель не меняются. Подписанный новый APK нужен для появления мобильного экрана.
