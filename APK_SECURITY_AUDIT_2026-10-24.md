### A01. PDF.js: приоритетный риск общего стека документов

В `public/vendor/pdfjs/pdf.min.js` версия **3.11.174**. Оба веб-компонента дополнительно загружают
ту же версию с CDN:

- `resources/js/DocumentViewer/SecureDocumentViewer.jsx:572,590` — getDocument({data: arrayBuffer}).
- `resources/js/NaryadViewer/NaryadViewer.jsx:269,279` — getDocument(pdfUrl).

В этих вызовах не установлен `isEvalSupported: false`. Для старой PDF.js опубликована
CVE-2024-4367: специально подготовленный PDF при включённом eval может выполнить JavaScript
в контексте просмотрщика. Условие риска — доставка и открытие такого PDF; способ внедрения
в рабочие документы и эксплуатация на production не проверялись. Это не утверждение о получении
доступа к серверу или Android SecureStore.

**Важное различие:** в исходниках мобильного релиза `mobile/src/securePdfViewerHtml.js:104`
уже установлен `isEvalSupported: false`, то есть предусмотрена официальная mitigation этой CVE.
Флаг подтверждён в исходниках коммита релиза; его выполнение на устройстве здесь не инструментировалось.
Нельзя объявлять APK эксплуатируемым только по номеру PDF.js.

Действия: сначала явно отключить eval в обоих веб-вызовах, затем обновить PDF.js до проверенной
поддерживаемой версии во всех местах, включая worker и мобильный просмотрщик; проверить CSP,
отказ от неконтролируемого CDN-кода и регрессии рендеринга/поиска. Минимальная версия исправления
старой CVE не означает рекомендуемую актуальную версию. У новых веток есть отдельные advisories.

Источники: [CVE-2024-4367 и mitigation от Mozilla](https://github.com/mozilla/pdf.js/security/advisories/GHSA-wgrm-67xf-hhpq),
[отдельный advisory новых веток PDF.js](https://github.com/mozilla/pdf.js/security/advisories/GHSA-hq66-cqwq-w95j).

### A02. Неограниченный срок мобильного токена

`config/sanctum.php:53` — expiration=null; это также подтверждено в production config.
`Api/Mobile/AuthController.php:38` создаёт токен без expires_at, с обычными default abilities.
При утечке Bearer-токена доступ сохраняется до отзыва: нового мобильного входа, logout,
блокировки аккаунта или восстановления пароля. Не требуется исходный APK: API аутентифицирует токен.

Действия: согласовать срок жизни и UX повторного входа/обновления токена; явно задавать expires_at,
проверить отзыв и очистку, разделение устройств и способности токенов там, где это необходимо.
Не ставить очень короткий срок без изменения клиента — это приведёт к регулярному разлогиниванию.
Сейчас вход также удаляет все токены с именем mobile, поэтому два мобильных устройства вытесняют друг друга.

Источник: [Sanctum token expiration](https://laravel.com/docs/12.x/sanctum#token-expiration).

### A03. Публикация не обеспечивает обязательных проверок

`mobile/scripts/publish-installers.sh:15-19` принимает любой существующий файл с расширением .apk
и выполняет cp на конечное имя. Нет обязательной проверки apksigner, ожидаемого сертификата,
packageName, versionCode, release/debug flags, хеша, защиты от параллельной публикации и проверки после выдачи.
Во время cp может быть доступен неполный файл.

Последняя выкладка 1.0.4 эти проверки и атомарную замену выполнила вручную; сам скрипт их не гарантирует.
Это риск процесса, не доказательство подмены текущего APK.

Действия: единый release-скрипт с fail-closed проверками, pinned fingerprint, проверкой версии,
временным файлом на той же FS, atomic rename, блокировкой параллельного запуска, резервной копией,
метаданными source commit/version/hash и последующей проверкой скачивания.
При необходимости независимого доверия к update metadata — отдельная криптографическая подпись;
JSON-хеш на том же взломанном сервере не создаёт независимую защиту.

### A04. Неявная политика cleartext

В упакованном release manifest отсутствуют `usesCleartextTraffic` и `networkSecurityConfig`.
В app.config.js вычисляется usesCleartextTraffic, но в проверенном бинарнике явный запрет не появился.
Production API URL — HTTPS. Для современного Android действуют безопасные defaults targetSdk,
однако minSdk=24, и полагаться на одинаковое поведение всех поддерживаемых платформ нельзя.
Обнаружение не означает, что приложение сейчас отправляет пароль по HTTP: такой передачи не наблюдалось.

Действия: закрепить release-политику через воспроизводимую native-конфигурацию, разрешая cleartext
только в изолированных debug-исключениях; проверять итоговый manifest и HTTP-отказ на Android 7/8 и современных версиях.
Запретить небезопасный API URL в release. Не отключать TLS validation и не добавлять trust-all сертификаты.

Источник: [Android Network Security Configuration](https://developer.android.com/privacy-and-security/security-config).

### A05. Невоспроизводимость native hardening и signing

`mobile/android` целиком исключён из git, tracked native-файлов нет. Настройка custom release signing
находится в локальном app/build.gradle, читает внешний keystore.properties и корректно падает при его отсутствии.
Секреты вынесены правильно, но важная несекретная логика сборки не воспроизводится из одного checkout.
Prebuild, другой компьютер или EAS могут собрать приложение с другими настройками/сертификатом.

Права локального каталога подписи 0700, properties 0600; секретные значения не читались.
Keystore/properties не найдены среди отслеживаемых текущих файлов. Полная история git и
резервирование/доступность ключа после потери компьютера не проверены.

Действия: хранить несекретную настройку в config plugin/контролируемом build script либо осознанно
версионировать native-проект; ключ оставить внешним. Проверить повторяемость чистой сборки и EAS,
шифрованную резервную копию ключа, права файла keystore и регламент восстановления.

### A06. Разрешения APK

В итоговом APK присутствуют SYSTEM_ALERT_WINDOW, READ_EXTERNAL_STORAGE/WRITE_EXTERNAL_STORAGE
(ограничены API 32), READ_MEDIA_IMAGES, а также media playback, biometric и capture-related permissions.
Для overlay-разрешения в просмотренных функциях нет обоснования. Часть остальных может приходить от Expo-модулей;
READ_MEDIA_IMAGES нельзя удалять вслепую без проверки screenshot listener на поддерживаемых Android.
Наличие разрешения не доказывает его выдачу пользователем или злоупотребление.

Действия: построить permission → функция → Android version карту, убрать только ненужное через
Expo/native configuration, проверять merged manifest и регрессии медиаплеера/защиты документов.

### A07. Остаточный доступ по подписанной ссылке

`Api/Mobile/DocumentController.php:73`, NaryadController и TrainingController выдают signed URLs на 30 минут.
`routes/api.php` защищает stream signature, но не Sanctum; `FileController` не перепроверяет владельца,
его активность или текущие роли. Для training есть проверка активности материала.

Следствие по коду: уже выданная URL продолжает работать до expires даже после logout/блокировки/сброса пароля
пользователя, пока ресурс доступен. URL является самостоятельной capability; это не обход криптоподписи.
Переданная другому человеку ссылка также не привязана к его личности. Вредоносный клиент может сохранить
полученные байты несмотря на запреты кнопок/скриншотов в официальном приложении.

Это существующее архитектурное решение, не менялось при аудите. Согласовать требования к немедленному отзыву,
перед изменениями доступа к документам/квизам получить утверждение по AGENTS.md. Варианты: более короткий TTL
с обновлением для видео/Range либо server-side grant с отзывом. Не передавать Bearer в URL.

### A08. Зависимости

Проверен отдельный lockfile из коммита 2b8d41d, не локальный 1.0.5: `npm audit --omit=dev --json`.
Результат: **8 затронутых dependency-узлов: 5 high, 3 moderate**, а не восемь независимых дыр в Android runtime.
Цепочки включают Expo CLI/code-signing/config-plugins, node-forge 1.4.0,
uuid 7.0.3, zod 3.25.76 и xcode. Прямо перечисленный expo содержит также build tooling, поэтому omit=dev
не отделяет native/runtime от build-time. Достижимость уязвимых функций из APK не доказана.

Идентификаторы advisory из npm: GHSA-86w9-cpqp-85rv (node-forge), GHSA-w5hq-g745-h8pq (uuid),
GHSA-mrhx-c7xc-m3w5 (zod). Для uuid проблема касается v3/v5/v6 с внешним буфером,
а не любого UUID-вызова: [advisory разработчика](https://github.com/uuidjs/uuid/security/advisories/GHSA-w5hq-g745-h8pq).

Действия: отдельно разобрать advisory и достижимость, обновить совместимые зависимости SDK 57,
пересобрать и протестировать. Не запускать `npm audit fix --force`: автоматический совет audit
в этом окружении предлагает downgrade Expo до 44.0.6, что несовместимо с текущим приложением.
Сырые результаты проверки сохранены во временном `/tmp/arm-apk-security-deps/audit.json`.

### A09. Сертификат домена без www

Проверка HTTPS `https://xn---15-7edz.xn--p1ai/install` завершилась curl 60 — hostname mismatch.
Адрес с www проходит TLS. Клиент 1.0.4 нормализует API к www, поэтому обход уже есть.
Но ручной переход/старые ссылки без www по-прежнему дают ошибку доверия; редирект после TLS её не исправит.

Действия: сертификат с SAN для обоих доменов, затем канонический редирект и проверка обоих имён.
Не предлагать пользователям обходить предупреждение браузера.

### A10. R8 выключен

Локальная native release-конфигурация использует enableMinifyInReleaseBuilds=false по умолчанию,
в gradle.properties нет включающего override. Это облегчает анализ Java/Kotlin и увеличивает сборку,
но само по себе не даёт доступа к API. Не доказано сравнением DEX, что каждая библиотека не обфусцирована.

Действия: включать оптимизацию отдельной итерацией с keep rules и smoke-тестами всех native-модулей.
R8 не превращает JS/Hermes bundle в секрет и не заменяет авторизацию.

## Что подтверждено положительно

- Подпись APK корректна и совпадает с зафиксированным release-сертификатом; хеш скачанного файла совпадает.
- APK не содержит явного debuggable=true, исходные source maps не найдены.
- Нет key/env-файлов с типовыми именами внутри APK. По ограниченным шаблонам в Hermes bundle не обнаружены
  private-key headers, Telegram bot tokens и AWS access-key IDs. Это не полный secret scan и не доказательство отсутствия всех секретов.
- SecureStore используется для Bearer. Упакованные backup XML включают sharedpref и явно исключают SecureStore
  и для cloud backup, и для device transfer. При allowBackup=true утечка токена через backup не подтверждена.
- Минимально открытые exported components: MainActivity (launcher/deep link) и AndroidX ProfileInstallReceiver
  с permission android.permission.DUMP; прочие показанные service/providers закрыты.
- Expo updates disabled в manifest — активного неподписанного OTA JS-канала не обнаружено.
- Production APP_DEBUG=false; .env 0600. Каталог раздачи 0755 и APK 0644 принадлежат deploy.
  Публичное чтение APK является выбранным способом распространения, не обходом доступа к данным.
- HTTPS www: HSTS и nosniff в ответе, современный targetSdk. Анонимный GET /api/mobile/me получает 401.
- Login ограничен throttle; роли проверяются до выдачи document URL; токены отзываются при восстановлении/блокировке.
- Bearer не передаётся в WebView; PDF загружается байтами, WebView incognito/cache=false/file access=false.

## Очерёдность работ

1. Отдельная небольшая правка PDF.js mitigation на вебе; затем план обновления PDF.js.
2. Защищённый release/publish script и воспроизводимая signing-конфигурация.
3. Явная release network policy и обоснованный набор permissions, проверка на старых Android.
4. Согласовать срок токенов и отзыв файловых grants, затем реализовать с тестами.
5. Совместимые dependency updates и R8 отдельными итерациями.
6. Только затем панель безопасности на существующих Filament/ClickHouse событиях.

Не внедрять X-App-Signature как доказательство подлинности клиента; хеш сертификата публичен и заголовок подделывается.
Не считать SHA-256 рядом с APK независимой защитой от компрометации сервера.

Ручная проверка восстановления пароля остаётся у тестировщика; её статус сохранён в PROFILE_RECOVERY_PLAN.md.
